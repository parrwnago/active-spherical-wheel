These compact NumPy arrays reproduce the I-62 fixed-grid retrospective tolerance
sweep without ROS, MuJoCo or the original large logs. They contain synchronized
cached maximum joint-load residual, observed force magnitude and radius, gate
validity, original I-60 proposal acceptance and native/proposal family labels,
fixed I-61 evaluation masks and truth labels, and cached point distances.

The point mask is fixed before tuning and requires finite native, A-hybrid and
truth-equivalent points. A uses the original accepted proposal or the native
fallback; an invalid unaccepted proposal does not remove its native fallback
sample. The raw proposal distance can therefore be nonfinite at an abstention;
it is selected only when the accepted-proposal policy is used.

The gate and all grid metrics, folds, selections and selected family flags are
recomputed by `tolerance_sweep.py`. Geometry, observer residuals, original
proposal scoring, and synchronized truth matching are cached inputs and are
not regenerated by this compact replay. Oracle geometry compatibility is a
diagnostic under the observed force and a single-resultant model; it is not an
independent true contact-force measurement.

All three episodes had already been inspected. Leaving out one complete start
phase is retrospective internal validation, not evidence from an unseen robot
run. No live controller, momentum observer or feedforward setting is changed.
No simulation is run. The producer input projection hashes and source bindings
are retained alongside these arrays.
